claude-vault-starter · from the workflow talk

Your own vault + agent loop, in ~10 minutes.

One folder of markdown that is your notes, a git repo, and the context every Claude Code session starts with, plus the cron loop that keeps it synced and the hooks that save every session. Mechanisms only: no one's preferences, no personal config, nothing to untangle.

1Let Claude set it up

Paste this into any Claude Code session on your machine. Claude looks at the machine first (how many sessions you have, which repos, whether you already keep notes), asks four short questions about how you work, proposes a shaped setup, Seed (notes + memory, nothing speaks) / Scholar (+ per-repo context, weekly distill, tidy-up) / Operator (+ agents that message you), installs only that, walks you through one real loop, and leaves Meta/Vault Setup.md with an undo line per piece and a two-week check-in:

Fetch https://jeremy-collins.com/vault/PROMPT.md (curl works) and follow its instructions to set up claude-vault-starter for me.

click the box to select it

2…or by hand

curl -LO https://jeremy-collins.com/vault/starter.tar.gz
tar xzf starter.tar.gz && cd claude-vault-starter
./setup.sh

Idempotent: safe to re-run any time. It tells you everything it does, shows the crontab before installing it, and asks first. Feature-gate with STARTER_FEATURES=none (core only) or a comma list of archive, comment-loop.

3What you get

With the assisted setup, auto-sync, session archive, comment-loop, and the Slack bridge are opt-in. Everything else always lands (and is inert until you call it).

4Two optional steps that make it yours

# back it up + enable multi-machine sync (private repo)
gh repo create vault --private --source ~/vault --push

# write today's note, then open any Claude session in ~/vault
echo "- trying the starter kit" >> ~/vault/$(date +%F).md
  • Second machine: clone your repo to ~/vault, run ./setup.sh again, then rm ~/.vault/.is_primary there.
  • Obsidian (optional): open ~/vault as a vault. It's just markdown; the system doesn't care what editor you use.

5Deliberately not included

Coding-style preferences, output styles, permission settings, and pipelines tied to one person's accounts (eval watchers, channel responder, account rotation). Those are shaped around one person's setup and taste. This kit is the rails they run on. Generic versions of everything else (organizer, digest, task agents, calendar/Todoist feeds) are in bells & whistles above. Build your own agents on top: start from example-agent, put it in cron, wrap outgoing ones in vault-run-if-primary, and they inherit the same guarantees.

Want one of the team-specific pieces walked through, say the channel responder or the repo digest? Ask Jeremy; each one is a ~1-file script plus a token, and the Slack-token slide in the deck covers the hard part.

6If something looks off

  • ~/.local/bin not on PATH → export PATH="$HOME/.local/bin:$PATH" in your shell rc.
  • Hooks not firing → they're plain JSON in ~/vault/.claude/settings.json (SessionStart) and ~/.claude/settings.json (Stop); setup.sh never overwrites existing hooks and leaves .bak files.
  • Sync conflicts → only non-markdown files can conflict; git status in ~/vault shows exactly what.
